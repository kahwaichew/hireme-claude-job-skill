# Essential HR questions

Ask only these during setup, all in one short message. The user can skip any of them.

1. **Reason for leaving**: for each past job, and the current one if they're looking. Polish each using the "Reasons for leaving" rules in SKILL.md.
2. **Last drawn salary**: the amount, currency and whether it's monthly or yearly. Mention that it's optional; some users and countries don't share this.
3. **Expected salary**: a range, with currency and period.
4. **Notice period / earliest start date.**
5. **Visa sponsorship or work permit**: do they need sponsorship to work in the countries they're targeting?

Example setup message:

> A few quick HR questions. Recruiters ask these a lot, so I'll prepare answers for you. Skip any you like.
> 1. Why did you leave (or why are you leaving) each job? Be honest; I'll help you phrase it professionally.
> 2. Your last drawn salary?
> 3. Your expected salary range?
> 4. Your notice period?
> 5. Do you need visa sponsorship for the countries you're applying to?

## How to phrase the salary and notice answers

- **Expected salary:** give a range anchored on the role and market. If the user wants to delay, use something like: "I'd like to understand the full scope first, but I'm looking at around X to Y."
- **Last drawn salary:** state it plainly and calmly if the user is comfortable sharing it. Where asking is uncommon or restricted, they can redirect to expected salary instead.
- **Notice period:** state it clearly, and mention flexibility if there is any ("2 months, though I may be able to arrange an earlier release").
- **Visa sponsorship:** a short factual answer, with no apology.

## Other interview questions (only when the user asks)

Don't collect these during setup. When the user asks about a question like "tell me about yourself", "why this company", "strengths and weaknesses" or "describe a challenge you solved", draft the answer from their experience. For behavioural questions, use a short STAR structure, and ask the user for a real example rather than inventing one.
